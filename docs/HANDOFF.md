# 两人＋两个 agent 的交接

## A：你／retrieval 分支
已完成：官方 BM25、固定数据、输出格式。
下一项：本地 embedding 下载与缓存、Dense Retrieval，输出相同 JSONL。保持 content-only baseline。先不要随意设计复杂图或根据测试集调参。

## B：队友／qa-eval 分支
已完成输入：两个真实 BM25 开发样例；可用 CPU 命令重建全部 90 个开发结果。
下一项：本地模型接口、官方 QA/judge 提示词与评分流程。先跑少量开发问题，验证解析和评分，再批量运行。question/answer 从原始文件按 uid 连接，answer 仅供 judge。

## 共同
先检查每类至少 2 个开发案例，区分检索缺证据和回答错误；再选一种小改进。共同写报告，A 写方法，B 写结果与失败分析。最终相互检查。

## 每次交接只写这些
- 分支和 commit
- 修改的模块及接口影响
- 运行命令和配置
- 结果位置（HPC 路径）与是否完整
- 测试结果、已知限制、下一步

不要传 SSH 私钥/密码，不复制整个 agent 聊天作为唯一交接。HPC 使用各自 checkout，共享只读模型缓存；正式 GPU 作业统一登记，避免重复运行。
